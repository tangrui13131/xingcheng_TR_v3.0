# 积分商城兑换审核功能完整实现

## 现状分析

当前兑换审核功能处于纯前端demo阶段：
- 用户端 `PointsMall.vue` 兑换仅操作 localStorage，无后端调用
- HR端 `RedemptionAudit.vue` 使用5条硬编码样本数据，审核操作不持久化
- 后端缺失：无兑换订单表、无Controller、无审核接口
- 已有基础：`sys_points_log` 表和对应的 Domain/Mapper/Service 已实现

## Task 1: 创建数据库兑换订单表和后端实体层

**目标**: 建立兑换订单的数据存储基础

**数据库** - 新建 `sql/redemption.sql`，创建 `sys_redemption` 表：
- `id` BIGINT PK AUTO_INCREMENT
- `user_id` BIGINT NOT NULL（申请人）
- `product_name` VARCHAR(255)（商品名称）
- `points_cost` INT NOT NULL（消耗积分）
- `status` CHAR(1) DEFAULT '0'（0=待审核, 1=已通过, 2=已驳回，遵循若依字典规范）
- `apply_time` DATETIME DEFAULT CURRENT_TIMESTAMP
- `audit_time` DATETIME（审核时间）
- `auditor_id` BIGINT（审核人ID）
- `reject_reason` VARCHAR(500)（驳回原因）
- `remark` VARCHAR(255)
- 索引：`idx_user_id`, `idx_status`

**后端 Domain** - 新建 `xingchen-system/src/main/java/com/xingchen/system/domain/SysRedemption.java`
- 继承 BaseEntity，定义上述字段，添加额外查询字段（userName, deptName 用于联表展示）

**后端 Mapper** - 新建：
- `SysRedemptionMapper.java` - 接口定义（selectList, selectById, insert, update）
- `SysRedemptionMapper.xml` - SQL映射，包含关联 sys_user + sys_dept 的联表查询

## Task 2: 开发后端 Service 和 Controller

**目标**: 实现完整的兑换审核业务逻辑和REST接口

**Service 层** - 新建 `ISysRedemptionService.java` + `SysRedemptionServiceImpl.java`：
- `submitRedemption(SysRedemption)` - 用户提交兑换：校验积分余额 -> 冻结积分（记录 sys_points_log） -> 创建待审核订单
- `selectRedemptionList(SysRedemption)` - 分页查询兑换列表（支持按状态筛选）
- `selectRedemptionById(Long id)` - 查询单条详情
- `approveRedemption(Long id)` - HR通过：更新状态为已通过，记录审核人和时间
- `rejectRedemption(Long id, String reason)` - HR驳回：更新状态为已驳回，退还积分（记录 sys_points_log sourceType=4）
- `selectMyRedemptions(Long userId)` - 用户查询自己的兑换记录

**Controller 层** - 新建 `xingchen-admin/.../controller/system/SysRedemptionController.java`：
- `POST /system/redemption/submit` - 用户提交兑换申请
- `GET /system/redemption/list` - HR查询兑换列表（分页+筛选）
- `GET /system/redemption/myList` - 用户查询自己的兑换记录
- `PUT /system/redemption/approve/{id}` - HR通过审核
- `PUT /system/redemption/reject/{id}` - HR驳回审核（body含reason）

**权限配置**: Controller方法添加 `@PreAuthorize` 注解，submit/myList 仅需登录，list/approve/reject 需要 `hr:redemption:audit` 权限。
