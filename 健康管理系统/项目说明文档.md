# 星辰健康管理系统 v3.9.2

> 基于 Spring Boot 4.0 + Vue 3 的企业级健康管理平台，深度融合「健康打卡 - 积分激励 - AI 智能分析」三位一体的数字化健康管理生态。

---

## 一、项目概述

星辰健康管理系统是一套面向企业的健康管理数字化解决方案，采用前后端分离架构。系统以「员工健康」为核心，通过游戏化健康打卡获取积分、积分兑换健康商品、AI 智能分析健康趋势，构建了完整的健康管理闭环。系统分为**管理后台**（面向管理员/HR）和**用户前台**（面向普通员工）两大入口，并集成了基于 Kimi 大模型的多模态 AI 助手，为健康管理注入智能化能力。

## 六、核心业务流程

### 6.1 健康打卡与积分体系

```
员工登录 → 进入首页 → 点击「健康充电站」
  → 渐进式问答（3 道题：睡眠质量 / 颈椎状态 / 饮水情况）
  → 每题选择后即时反馈（鼓励文案 + 色彩提示）
  → 完成打卡 → 系统记录 → 积分入账（+10 分/日）
  → 连续打卡额外奖励
  → 积分可在「积分商城」兑换健康商品
```

**积分流水规则（`sys_points_log` 表）：**

| 操作类型 | 参与场景 | 说明 |
|----------|----------|------|
| 收入（1） | 每日打卡（1） | 每日完成打卡 +10 分 |
| 收入（1） | 连续打卡奖励（2） | 连续 N 天打卡额外奖励 |
| 支出（2） | 兑换商品消耗（3） | 积分商城兑换商品扣分 |
| 收入（1） | HR 手动退还（4） | 审核驳回时退还积分 |

### 6.2 积分商城兑换流程

```
员工选择商品 → 确认兑换 → 积分扣除 → 生成兑换申请
  → HR 审核通过 → 发放商品
  → HR 审核驳回 → 积分退还
```

**商城商品示例：** 瑞幸咖啡兑换券(150分)、定制健康水杯(200分)、午休颈枕(300分)、眼部按摩仪(800分)、半天带薪健康假(1000分)、智能运动手环(2500分)

### 6.3 AI 助手交互流程

```
用户输入文本 / 上传图片 → 前端 Base64 编码
  → POST /ai/chat/send { message, image? }
  → 后端 AiController 判断是否含图片
    → 纯文本：调用 moonshot-v1-8k 模型
    → 含图片：调用 moonshot-v1-8k-vision-preview 模型
  → 组装 Moonshot API 请求 → 转发至 https://api.moonshot.cn/v1/chat/completions
  → 解析响应 → 返回 AI 回复文本
  → 前端气泡式展示（打字机效果、自动滚动）
```

### 7.2 积分流水表结构 (`sys_points_log`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | bigint PK | 流水唯一标识 |
| `user_id` | bigint | 发生积分变动的员工 ID |
| `operate_type` | tinyint | 操作类型：1=收入，2=支出 |
| `source_type` | tinyint | 场景：1=每日打卡，2=连续打卡奖励，3=兑换消耗，4=HR退还 |
| `points` | int | 本次波动分值（绝对值） |
| `reference_id` | bigint | 业务关联 ID（打卡记录/兑换订单） |
| `remark` | varchar(255) | 波动说明 |
| `create_time` | datetime | 发生时间 |

### 7.3 数据源配置

- 数据库：MySQL 8.x，库名 `ry-vue`
- 连接池：Alibaba Druid，初始 5 连接，最大 20 连接
- 支持主从数据源配置（默认从库关闭）
- Druid 监控台：`/druid/*`，账号 `xingchen` / 密码 `123456`

## 八、安全体系

| 安全维度 | 实现方式 |
|----------|----------|
| 认证机制 | Spring Security + JWT Token（Header: `Authorization`） |
| 令牌管理 | Token 有效期 30 分钟，Redis 存储，支持在线用户踢出 |
| 验证码 | Kaptcha 数学计算型验证码 |
| 密码安全 | RSA 加密传输 + BCrypt 哈希存储，错误 5 次锁定 10 分钟 |
| XSS 防护 | 全局 XSS 过滤器（排除通知公告接口） |
| 防盗链 | Referer 白名单校验（默认关闭） |
| 请求防重 | 自定义注解 `@RateLimiter` 支持接口限流 |
| 数据权限 | 基于角色的行级数据权限过滤（AOP 切面） |

### 10.2 后端启动

1. 启动 MySQL 和 Redis 服务
2. 导入数据库脚本：`sql/ry_20260321.sql` → `sql/points_log.sql` → `sql/quartz.sql`
3. 修改 `application-druid.yml` 中的数据库连接信息
